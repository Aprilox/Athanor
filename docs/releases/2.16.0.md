## What's new in 2.16.0

A project now gets to its first line of code much sooner, and the quota goes to the code rather than to everything around it.

- **A time-boxed framing.** The first cycle of a project only writes the plan, in 25 minutes at most (`FRAMING_MAX_MIN`). Up to 3 `scout` sub-agents read the attachments and the existing code at once, on Sonnet. The lead writes the requirements, the architecture and the plan itself, then the `critic` checks the plan once. No code, no installation, no test of a tool and no demo content in this cycle: demo content becomes a milestone of its own. Past the time box, the plan as it stands goes ahead; with no plan at all, a short cycle writes it from what is already there.
- **Every milestone is a self-contained sheet:** its files, its dependencies, its acceptance criteria and what to read. A worker needs nothing else.
- **A model for each role.** `FRAMING_MODEL` for the framing (empty = the lead's model) and `WORKER_MODEL` for the parallel workers, **Sonnet by default**. The new `scout` runs on Sonnet; the lead keeps `MODEL`.
- **Workers that respect the quota.** Parallel mode starts with 2 workers and adds one each time a worker delivers, up to the chosen maximum. As soon as a worker meets the quota, no other one starts. If they all met it, the lead's verification is skipped.
- **A smarter quota pause.** When the limit hit is the account's own (5 hours, or the week), the pilot no longer switches to the fallback model, which shares that limit: it waits for the reset. After any quota pause, one milestone runs with the lead alone before workers start again, so a wave never fails all at once.
- **Shared solutions.** `.athanor/SOLUTIONS.md` (the project) and `tools/SOLUTIONS.md` (the PC, shared by every project) hold one line per problem already solved. Every agent reads them first and adds a line when it solves something. The pilot removes duplicates, keeps the latest 60 lines and merges what the parallel workers learned.
- **The toolchain is known from the start.** `.athanor/PC_TOOLS.md` now lists the versions of Node, npm, Python, PHP, Composer, Git, Java and the other usual tools, checked by the pilot, plus the portable installs already in `tools/`. The agents stop probing them.

## Nouveautés de la 2.16.0

Un projet arrive à sa première ligne de code bien plus tôt, et le quota sert au code plutôt qu'à tout ce qui l'entoure.

- **Un cadrage limité dans le temps.** Le premier cycle d'un projet n'écrit que le plan, en 25 minutes au plus (`FRAMING_MAX_MIN`). Jusqu'à 3 sous-agents `scout` lisent en même temps les pièces jointes et le code existant, sur Sonnet. Le chef écrit lui-même les exigences, l'architecture et le plan, puis le `critic` relit le plan une fois. Pas de code, pas d'installation, pas de test d'outil et pas de contenu de démo dans ce cycle : le contenu de démo devient un jalon à part. Une fois le temps écoulé, le plan tel qu'il est part en développement ; sans aucun plan, un court cycle l'écrit à partir de ce qui existe déjà.
- **Chaque jalon est une fiche autonome :** ses fichiers, ses dépendances, ses critères d'acceptation et ce qu'il faut lire. Un ouvrier n'a besoin de rien d'autre.
- **Un modèle par rôle.** `FRAMING_MODEL` pour le cadrage (vide = le modèle du chef) et `WORKER_MODEL` pour les ouvriers en parallèle, **Sonnet par défaut**. Le nouveau `scout` tourne sur Sonnet ; le chef garde `MODEL`.
- **Des ouvriers qui respectent le quota.** Le mode parallèle démarre avec 2 ouvriers et en ajoute un chaque fois qu'un ouvrier livre, jusqu'au maximum choisi. Dès qu'un ouvrier atteint le quota, plus aucun ne démarre. S'ils l'ont tous atteint, la vérification du chef est sautée.
- **Une pause de quota plus maligne.** Quand la limite atteinte est celle du compte (5 heures, ou la semaine), le pilote ne bascule plus sur le modèle de secours, qui partage cette limite : il attend la réouverture. Après toute pause de quota, un jalon est fait par le chef seul avant de relancer des ouvriers, pour qu'une vague n'échoue jamais d'un coup.
- **Des solutions partagées.** `.athanor/SOLUTIONS.md` (le projet) et `tools/SOLUTIONS.md` (le PC, partagé par tous les projets) contiennent une ligne par problème déjà résolu. Chaque agent les lit en premier et ajoute une ligne quand il résout quelque chose. Le pilote retire les doublons, garde les 60 dernières lignes et récupère ce que les ouvriers en parallèle ont appris.
- **Les outils sont connus dès le départ.** `.athanor/PC_TOOLS.md` liste désormais les versions de Node, npm, Python, PHP, Composer, Git, Java et des autres outils courants, vérifiées par le pilote, ainsi que les installations portables déjà présentes dans `tools/`. Les agents ne les sondent plus.

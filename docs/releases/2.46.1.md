## What's new in 2.46.1

- **A repository made on GitHub with a README is no longer a dead end.** Its branch has a history of its own (the README, licence or `.gitignore` GitHub adds), nothing in common with the project's, so Athanor refused both the push and *Get GitHub's work*, with no way out. *Manage → GitHub → Sort it out with GitHub's branch…* (also offered by *Get GitHub's work*, by the refused push and by *Start*) now gives two choices, each confirmed:
  - *Bring GitHub's files in*: the two histories merged, GitHub's files in the project; a file both have with different contents is left to Claude at its next cycle (`.athanor/MERGE_NEEDED.md`), nothing is lost;
  - *Replace GitHub's branch with this project*: a push over it, after showing the commits that would leave the branch, and only as you saw it (if GitHub changed meanwhile, nothing is replaced). The secret check still runs; never for several computers working together, never by the automatic push.
- **Create repositories without a window** (an option, off by default): *Settings → Options → GitHub → Keep the access (one sign-in)*. Creating a repository goes through GitHub's API, which the connection's key cannot reach, so it opened a sign-in each time; with this option one sign-in is kept on the computer, out of Claude's reach, used only to create repositories, and a new project's repository is then created at once. It opens the account's repositories: *Forget this access* and *Disconnect* remove it (it stays revocable on GitHub, Settings › Applications). An access revoked on GitHub is forgotten by itself, and the creation signs in again. In a terminal: on the GitHub page, *k* keeps it, *o* forgets it, *b* sorts out GitHub's branch.
- The terminal's GitHub page said *n* for *Create a private repository*; the key is *r*.
- **A shortcut to the installed Athanor.** The downloaded file installs Athanor in its own folder, which updates itself; the file itself stays the old version. *Settings → Options → Shortcut* (also offered once, at the top of the window, when Athanor was opened from the downloaded file) makes a shortcut in the folder you choose: an `Athanor.lnk` on Windows (the Desktop by default, and always the Start menu), an `athanor.desktop` on Linux (the desktop by default, and always the applications menu), an `Athanor.app` that opens the installed Athanor on macOS (Applications by default). In a terminal: `athanor raccourci [FOLDER]`, or *r* in Settings.
- **The downloaded file opened again.** Older than the installed Athanor: it changes nothing and opens the installed one (the window says so). The same version: the installed folder is checked against it and what is damaged or missing is put back (Athanor's files and its executable, never your data). Newer: it updates, as always.

## Nouveautés de la 2.46.1

- **Un dépôt créé sur GitHub avec un README n'est plus une impasse.** Sa branche a son propre historique (le README, la licence ou le `.gitignore` que GitHub ajoute), sans rien de commun avec celui du projet : Athanor refusait le push et *Récupérer le travail de GitHub*, sans aucune issue. *Gérer → GitHub → Régler la question avec la branche de GitHub…* (proposé aussi par *Récupérer le travail de GitHub*, par le push refusé et par *Démarrer*) donne désormais deux choix, chacun confirmé :
  - *Intégrer les fichiers de GitHub* : les deux historiques fusionnés, les fichiers de GitHub dans le projet ; un fichier présent des deux côtés avec des contenus différents est laissé à Claude à son cycle suivant (`.athanor/MERGE_NEEDED.md`), rien n'est perdu ;
  - *Remplacer la branche de GitHub par ce projet* : un push par-dessus, après avoir montré les commits qui quitteraient la branche, et seulement telle que vous l'avez vue (si GitHub a changé entre-temps, rien n'est remplacé). La vérification des secrets s'applique toujours ; jamais quand plusieurs ordinateurs travaillent ensemble, jamais par le push automatique.
- **Créer des dépôts sans fenêtre** (une option, désactivée par défaut) : *Réglages → Options → GitHub → Garder l'accès (une connexion)*. Créer un dépôt passe par l'API de GitHub, que la clé de la connexion n'atteint pas : une connexion s'ouvrait donc à chaque fois ; avec cette option, une connexion est gardée sur l'ordinateur, hors de portée de Claude, utilisée seulement pour créer des dépôts, et le dépôt d'un nouveau projet est alors créé aussitôt. Elle ouvre les dépôts du compte : *Oublier cet accès* et *Déconnecter* la retirent (elle reste révocable sur GitHub, Settings › Applications). Un accès révoqué sur GitHub est oublié tout seul, et la création se reconnecte. Dans un terminal : sur la page GitHub, *k* la garde, *o* l'oublie, *b* règle la question de la branche de GitHub.
- La page GitHub du terminal indiquait *n* pour *Créer un dépôt privé* ; la touche est *r*.
- **Un raccourci vers l'Athanor installé.** Le fichier téléchargé installe Athanor dans son propre dossier, qui se met à jour seul ; le fichier, lui, reste à l'ancienne version. *Réglages → Options → Raccourci* (proposé aussi une fois, en haut de la fenêtre, quand Athanor a été ouvert depuis le fichier téléchargé) crée un raccourci dans le dossier de votre choix : un `Athanor.lnk` sous Windows (le Bureau par défaut, et toujours le menu Démarrer), un `athanor.desktop` sous Linux (le bureau par défaut, et toujours le menu des applications), un `Athanor.app` qui ouvre l'Athanor installé sous macOS (Applications par défaut). Dans un terminal : `athanor raccourci [DOSSIER]`, ou *r* dans les Réglages.
- **Le fichier téléchargé rouvert.** Plus ancien que l'Athanor installé : il ne change rien et ouvre l'Athanor installé (la fenêtre le dit). La même version : le dossier installé est comparé à lui et ce qui est abîmé ou manquant est remis (les fichiers d'Athanor et son exécutable, jamais vos données). Plus récent : il met à jour, comme toujours.

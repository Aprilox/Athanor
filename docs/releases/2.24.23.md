## What's new in 2.24.23

A pilot that froze on every large image, all night long, in native Windows; and the first bugs of the Go pilot fixed.

- **Native Windows: Claude writes its stream straight into its log file.** Through Git Bash's pipe (`| tee | jq`), a line longer than the pipe (an image of 170 KB and more in the log: a Roblox Studio capture, a picture read) could stall Claude for good: no output, then the watchdog after 30 minutes, cycle after cycle. The same image read in a terminal took 8 seconds. Now there is no pipe between Claude and the pilot; the live display reads the log as it grows (`athanor affichage`). The Go pilot does the same in native Windows.
- **A session silent right after an image is named and stopped after 10 minutes** (instead of 30): "no activity for 10 min, right after an image of 460 KB". The next cycles ask Claude to keep its images small (a small copy before reading, captures saved to a file and shrunk) until an image as large goes through again (`athanor images`).
- **The same watchdog stop again and again raises an alert**: after 3 cycles in a row stopped by the watchdog, `.athanor/ALERT.md` and a 30-minute pause, instead of a restart every 2 minutes.
- **Go pilot (`PILOT_ENGINE=go`)**: the end of Claude's output could be seen before its exit code, and a successful cycle taken for an error (under load); `system/bin` was put twice in Claude's `PATH`; the settings file's name was printed in the live display. The **Engine of the pilot** setting is in Settings › Claude (advanced).
- **Checked**: 28 scenarios run with both engines and compared (log, live display, Claude's command lines and environment, commits, statistics, workshop, private folder), the log written directly included; the freeze after an image, its rule and its lifting; the Go unit tests.

## Nouveautés de la 2.24.23

Un pilote qui se figeait sur chaque grosse image, toute la nuit, en Windows natif ; et les premiers bugs du pilote Go corrigés.

- **Windows natif : Claude écrit son flux directement dans son fichier journal.** À travers le tuyau de Git Bash (`| tee | jq`), une ligne plus longue que le tuyau (une image de 170 Ko et plus dans le journal : une capture de Roblox Studio, une image lue) pouvait bloquer Claude pour de bon : plus rien, puis le chien de garde au bout de 30 minutes, cycle après cycle. La même image lue dans un terminal prenait 8 secondes. Désormais, aucun tuyau entre Claude et le pilote ; l'affichage en direct lit le journal au fil de l'eau (`athanor affichage`). Le pilote Go fait de même en Windows natif.
- **Une session muette juste après une image est nommée et arrêtée au bout de 10 minutes** (au lieu de 30) : « no activity for 10 min, right after an image of 460 KB ». Les cycles suivants demandent à Claude de garder ses images petites (une petite copie avant de lire, les captures enregistrées dans un fichier puis réduites), jusqu'à ce qu'une image aussi grosse passe de nouveau (`athanor images`).
- **Le même arrêt du chien de garde à répétition déclenche une alerte** : après 3 cycles d'affilée arrêtés par le chien de garde, `.athanor/ALERT.md` et une pause de 30 minutes, au lieu d'une relance toutes les 2 minutes.
- **Pilote Go (`PILOT_ENGINE=go`)** : la fin de la sortie de Claude pouvait être vue avant son code de sortie, et un cycle réussi pris pour une erreur (sous charge) ; `system/bin` était mis deux fois dans le `PATH` de Claude ; le nom du fichier de réglages s'affichait dans le direct. Le réglage **Moteur du pilote** est dans Réglages › Claude (avancé).
- **Vérifié** : 28 scénarios joués avec les deux moteurs et comparés (journal, affichage en direct, lignes de commande et environnement de Claude, commits, statistiques, atelier, dossier privé), journal écrit directement compris ; le gel après une image, sa consigne et sa levée ; les tests unitaires Go.

## What's new in 2.47.0

- **Fix with Claude.** When the test of an MCP server fails on this computer (a command that does not exist here, arguments written for another system, a package that changed its name…), *Fix with Claude* gives Claude Code the server's definition (the names of its keys, never their values), this system, the programs found here and the error. Claude may read the server's page on the web and answers with a configuration only; Athanor tests it exactly as it will run it and keeps it when the server answers, else gives the error back to Claude (three tries at most). A program missing here (node, uv, docker…) is said instead of worked around. The fix stays in this computer's library: *Undo the fix* puts back what it replaced. The same works for a plugin's servers.
- **Skills are tested too.** *Test* on a skill checks its header (without a name and a description, Claude never picks it) and each script: is its program here (python3 or python, node, bash…), does it parse, is it written for one system only (Windows line endings, `sed -i` without a suffix or `grep -P` on a Mac, a `C:\` path…). *Fix with Claude* rewrites a copy of the skill so that it runs on Windows, macOS and Linux and does the same; the copy is tested again and shown as a diff, and nothing is replaced before *Apply the fix* (*Undo the fix* afterwards).
- **Fixes for everyone.** Every fix, and every fault of Athanor's own way of running an extension that Claude names, is written in `logs/corrections/` of Athanor's folder. The *Skills & MCP* page lists them, and writes the verified catalog's fixes into a copy of Athanor's code (the system's variant of the entry only, the rest of the file untouched): commit and push, and every Athanor gets them. In a terminal: `athanor extensions corriger KIT PROJECT ID --appliquer`, `tester-skill`, `corriger-skill`, `appliquer-skill`, `annuler-skill`, `annuler-correction`, `corrections KIT`, `appliquer-corrections KIT CODE`.
- **Servers installed in the home now start in the cage on Linux and macOS.** The cage kept only the system's folders on its `PATH`: `uvx` in `~/.local/bin` (uv's own installer), `node` from nvm or volta, bun, deno and cargo's programs were "not found", although the cage let them be read. They are on the cage's `PATH` now, after the system's.

## Nouveautés de la 2.47.0

- **Corriger avec Claude.** Quand le test d'un serveur MCP échoue sur cet ordinateur (une commande qui n'existe pas ici, des arguments écrits pour un autre système, un paquet qui a changé de nom…), *Corriger avec Claude* donne à Claude Code la définition du serveur (les noms de ses clés, jamais leurs valeurs), ce système, les programmes trouvés ici et l'erreur. Claude peut lire la page du serveur sur le web et ne répond que par une configuration ; Athanor la teste exactement comme il la lancera et la garde quand le serveur répond, sinon il redonne l'erreur à Claude (trois essais au plus). Un programme qui manque ici (node, uv, docker…) est signalé au lieu d'être contourné. La correction reste dans la bibliothèque de cet ordinateur : *Annuler la correction* remet ce qu'elle a remplacé. Pareil pour les serveurs d'un plugin.
- **Les skills sont testés aussi.** *Tester* sur un skill vérifie son en-tête (sans nom ni description, Claude ne le choisit jamais) et chaque script : son programme est-il ici (python3 ou python, node, bash…), se lit-il, est-il écrit pour un seul système (fins de ligne Windows, `sed -i` sans suffixe ou `grep -P` sur Mac, un chemin `C:\`…). *Corriger avec Claude* réécrit une copie du skill pour qu'il tourne sous Windows, macOS et Linux en faisant la même chose ; la copie est testée de nouveau et montrée en diff, et rien n'est remplacé avant *Appliquer la correction* (*Annuler la correction* ensuite).
- **Des corrections pour tout le monde.** Chaque correction, et chaque défaut de la façon dont Athanor lance une extension que Claude désigne, est noté dans `logs/corrections/` du dossier d'Athanor. La page *Skills & MCP* les liste, et écrit les corrections du catalogue vérifié dans une copie du code d'Athanor (seulement la variante du système dans l'entrée, le reste du fichier intact) : commitez et poussez, et tous les Athanor les reçoivent. Dans un terminal : `athanor extensions corriger KIT PROJET ID --appliquer`, `tester-skill`, `corriger-skill`, `appliquer-skill`, `annuler-skill`, `annuler-correction`, `corrections KIT`, `appliquer-corrections KIT CODE`.
- **Les serveurs installés dans le dossier personnel démarrent maintenant dans la cage sous Linux et macOS.** La cage ne gardait que les dossiers du système dans son `PATH` : `uvx` dans `~/.local/bin` (l'installeur d'uv), `node` de nvm ou volta, les programmes de bun, deno et cargo étaient « introuvables », alors que la cage permettait de les lire. Ils sont maintenant dans le `PATH` de la cage, après ceux du système.

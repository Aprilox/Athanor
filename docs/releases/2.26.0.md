## What's new in 2.26.0

**One file.** A release is now a single executable per system: `Athanor.exe` (Windows), `athanor-linux`, `athanor-macos` (`-intel`, `-arm64` for the other processors). Nothing to unzip, and nothing is ever written next to it.

- **First launch**: Athanor says where it will keep its files (`%LOCALAPPDATA%\Athanor`, `~/.local/share/athanor`, `~/Library/Application Support/Athanor`) and asks first. *No*: it closes, nothing was written. Everything of its own goes there (its copy, settings and token, logs, tools); in your projects, only `.athanor/`.
- **Updates from the app**: when a new version is out, an *Update to X.Y.Z* button shows at the top of the window. *Update now* downloads the file of your system, checks it against the release's `SHA256SUMS.txt`, then Athanor closes, puts the new version in place and opens again; running pilots go on. *Settings › Options › Version* looks now, and can stop looking when Athanor opens. Only GitHub is asked, nothing about you is sent.
- **An installation made before** (a folder with `Athanor.exe`, `template/` and `athanor-config.json`) stays where it is: the new executable updates its files in place.
- **Lighter tool folder**: the Go sources (`app/`) are written into it only when a repair needs them (*Rebuild Athanor*, a repair by Claude).
- **Guided tour**: the rest of the window is dimmed around the place each step explains.
- **Linux**: *Setup & health* has its own list (no WSL, no Windows administrator task).
- **Native Windows**: *Git for Windows* is what is needed (git itself; Claude Code also runs its commands in its Git Bash, or in PowerShell without it); jq is optional, Athanor itself no longer uses it.
- The CI tests the single executable on Windows, Linux and macOS: nothing written before the consent, Athanor's folder installed, nothing next to the file.

## Nouveautés de la 2.26.0

**Un seul fichier.** Une version est désormais un seul exécutable par système : `Athanor.exe` (Windows), `athanor-linux`, `athanor-macos` (`-intel`, `-arm64` pour les autres processeurs). Rien à dézipper, et rien n'est jamais écrit à côté de lui.

- **Premier lancement** : Athanor dit où il va ranger ses fichiers (`%LOCALAPPDATA%\Athanor`, `~/.local/share/athanor`, `~/Library/Application Support/Athanor`) et demande d'abord. *Non* : il se ferme, rien n'a été écrit. Tout ce qui est à lui y va (sa copie, réglages et jeton, journaux, outils) ; dans vos projets, seulement `.athanor/`.
- **Mises à jour depuis l'application** : quand une nouvelle version sort, un bouton *Mettre à jour (X.Y.Z)* apparaît en haut de la fenêtre. *Mettre à jour maintenant* télécharge le fichier de votre système, le vérifie avec le `SHA256SUMS.txt` de la version, puis Athanor se ferme, met la nouvelle version en place et se rouvre ; les pilotes en cours continuent. *Réglages › Options › Version* regarde tout de suite, et peut ne plus regarder à l'ouverture. Seul GitHub est interrogé, rien sur vous n'est envoyé.
- **Une installation d'avant** (un dossier avec `Athanor.exe`, `template/` et `athanor-config.json`) reste où elle est : le nouvel exécutable met ses fichiers à jour sur place.
- **Dossier de l'outil allégé** : les sources Go (`app/`) n'y sont écrites que quand une réparation en a besoin (*Recompiler Athanor*, une réparation par Claude).
- **Visite guidée** : le reste de la fenêtre s'assombrit autour de la zone que chaque étape explique.
- **Linux** : *Installation & santé* a sa propre liste (ni WSL, ni tâche administrateur Windows).
- **Windows natif** : c'est *Git pour Windows* qu'il faut (git lui-même ; Claude Code lance aussi ses commandes dans son Git Bash, ou dans PowerShell sans lui) ; jq devient facultatif, Athanor lui-même ne s'en sert plus.
- La CI teste l'exécutable unique sous Windows, Linux et macOS : rien d'écrit avant l'accord, dossier d'Athanor installé, rien à côté du fichier.

## What's new in 2.44.0

- **Team, live: a direct link between the computers of a project.** *Overview → Team, live* (in a terminal: **M**, then *Team, live*): one computer becomes the team's master, any of them, project by project. It opens a link of its own, a Cloudflare tunnel separate from the remote access, which only answers the team's three calls: a team member can never reach the master's panel, its settings or its chat. *Invite a computer* gives an invitation (`https://….trycloudflare.com#123456`); on the other computer, *Join with an invitation*.
- **Every computer sees the whole team live**: every 10 seconds each one says what it builds and what it uses (the account's quota over 5 hours and over the week, cycles, cost, tokens, Ponytail, eco mode), and gets back everyone's state. The master can remove a computer at any time.
- **Pairing**: a 6-digit code, used once, valid 10 minutes, dead after 5 wrong tries, a second's wait after each one. **The right code is not enough: the master accepts each computer on its screen** (« PC-B wants to join the team », *Accept* / *Refuse*, with a notification); a request left unanswered is gone after 10 minutes. Accepted, the computer gets a token of its own (the master keeps only its hash), which opens nothing but the team's calls.
- **The tunnel's address changes when it starts again**: the master publishes the new one in its presence on GitHub, encrypted with the team's key (AES-GCM), and the others find it there by themselves.
- GitHub stays where the code goes and what the team falls back on: when the master does not answer, the computers go on as before. Next: the workshop and the orders through the direct link, then a fallback encrypted on GitHub.
- **Overview → Usage: the cache tile says whose it is.** « 98 % read from Claude's own cache, reading −87 % » is Claude's own prompt cache (Anthropic's, always on, over all the cycles), not a saving of an Athanor option: it is shown in grey, and the line below says that Ponytail, RTK and the eco mode are measured apart. In a terminal, it has a line of its own.
- **Blender (MCP) on macOS and Linux.** The verified catalog's Blender runs Blender Lab's server with uv on the computer itself (outside the cage, like on Windows), with instructions for Claude that no longer speak of a locked Windows session; a server installed with the Windows configuration moves to it by itself. On Linux the `blender` command finds the computer's Blender (on the PATH, the Snap, or the Flatpak `org.blender.Blender`), runs it as it is (`blender -b -P script.py`) and opens its window detached on a `.blend` of the project, for the pilot before each cycle; `.athanor/PC_TOOLS.md` lists it. On macOS the pilot already opened `Blender.app`.
- The catalog's servers run outside the cage on macOS and Linux (Roblox Studio, Blender) can now be saved as they are from *View / edit*; changing their command is refused.

## Nouveautés de la 2.44.0

- **Équipe, en direct : un lien direct entre les ordinateurs d'un projet.** *Suivi → Équipe, en direct* (dans un terminal : **M**, puis *Équipe, en direct*) : un ordinateur devient le maître de l'équipe, n'importe lequel, projet par projet. Il ouvre un lien à lui, un tunnel Cloudflare séparé de l'accès à distance, qui ne répond qu'aux trois appels de l'équipe : un membre de l'équipe ne peut jamais atteindre le panneau du maître, ses réglages ni sa discussion. *Inviter un ordinateur* donne une invitation (`https://….trycloudflare.com#123456`) ; sur l'autre ordinateur, *Rejoindre avec une invitation*.
- **Chaque ordinateur voit toute l'équipe en direct** : toutes les 10 secondes, chacun dit ce qu'il construit et ce qu'il consomme (le quota du compte sur 5 heures et sur la semaine, les cycles, le coût, les jetons, Ponytail, le mode éco), et reçoit l'état de tous. Le maître peut retirer un ordinateur à tout moment.
- **Appairage** : un code à 6 chiffres, à usage unique, valable 10 minutes, mort après 5 essais faux, une seconde d'attente après chacun. **Le bon code ne suffit pas : le maître accepte chaque ordinateur sur son écran** (« PC-B veut rejoindre l'équipe », *Accepter* / *Refuser*, avec une notification) ; une demande sans réponse disparaît au bout de 10 minutes. Accepté, l'ordinateur reçoit un jeton à lui (le maître n'en garde que l'empreinte), qui n'ouvre que les appels de l'équipe.
- **L'adresse du tunnel change quand il redémarre** : le maître publie la nouvelle dans sa présence sur GitHub, chiffrée avec la clé de l'équipe (AES-GCM), et les autres la retrouvent là d'eux-mêmes.
- GitHub reste là où passe le code et ce sur quoi l'équipe se replie : quand le maître ne répond pas, les ordinateurs continuent comme avant. Ensuite : l'atelier et les ordres par le lien direct, puis un secours chiffré sur GitHub.
- **Suivi → Consommation : la tuile du cache dit à qui il est.** « 98 % lu depuis le cache propre à Claude, lecture −87 % » est le cache de prompt propre à Claude (celui d'Anthropic, toujours actif, sur tous les cycles), pas un gain d'une option d'Athanor : il s'affiche en gris, et la ligne en dessous précise que Ponytail, RTK et le mode éco sont mesurés à part. Dans un terminal, il a sa propre ligne.
- **Blender (MCP) sous macOS et Linux.** Le Blender du catalogue vérifié lance le serveur de Blender Lab avec uv sur l'ordinateur lui-même (hors de la cage, comme sous Windows), avec des consignes pour Claude qui ne parlent plus de session Windows verrouillée ; un serveur installé avec la configuration Windows y passe tout seul. Sous Linux, la commande `blender` trouve le Blender de l'ordinateur (dans le PATH, le Snap ou le Flatpak `org.blender.Blender`), le lance tel quel (`blender -b -P script.py`) et ouvre sa fenêtre détachée sur un `.blend` du projet, pour le pilote avant chaque cycle ; `.athanor/PC_TOOLS.md` le mentionne. Sous macOS, le pilote ouvrait déjà `Blender.app`.
- Les serveurs du catalogue lancés hors de la cage sous macOS et Linux (Roblox Studio, Blender) peuvent désormais être enregistrés tels quels depuis *Voir / modifier* ; changer leur commande est refusé.

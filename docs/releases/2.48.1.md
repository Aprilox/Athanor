## What's new in 2.48.1

- **Disconnecting from GitHub no longer unlinks the projects.** The projects that push with this computer's connection stay linked while it is disconnected: a push says "This computer is no longer connected to GitHub: connect it again…", instead of a refused key and "Link the project again". Connected again, they push with the new key at once, nothing to link again, and the ones whose last push was refused for want of the connection say they push again.
- **GitHub's refusals told apart.** A key GitHub does not accept (`Permission denied (publickey)`) says to connect again; a repository the account cannot reach says so, with the account's name; an error of the computer itself (a file another program keeps busy, "Permission denied" on a local file) is no longer taken for GitHub refusing the key. *Test the connection* also shows what git or ssh said, under its message (in the window and in the terminal).
- **A repository created twice.** When an earlier try had created the repository and then stopped, creating it again failed with "Repository creation failed. (HTTP 422)": the same repository, still empty, is now linked; one that already has commits is never taken without being chosen (*Use one of my repositories*). GitHub's own reason is said when it refuses a name.

## Nouveautés de la 2.48.1

- **Se déconnecter de GitHub ne délie plus les projets.** Les projets qui envoient avec la connexion de cet ordinateur restent liés pendant qu'il est déconnecté : un envoi dit « Cet ordinateur n'est plus connecté à GitHub : reconnectez-le… », au lieu d'une clé refusée et de « Liez à nouveau le projet ». Une fois reconnectés, ils envoient aussitôt avec la nouvelle clé, rien à relier, et ceux dont le dernier envoi avait été refusé faute de connexion disent qu'ils envoient de nouveau.
- **Les refus de GitHub distingués.** Une clé que GitHub n'accepte pas (`Permission denied (publickey)`) dit de se reconnecter ; un dépôt que le compte n'atteint pas le dit, avec le nom du compte ; une erreur de l'ordinateur lui-même (un fichier qu'un autre programme garde ouvert, « Permission denied » sur un fichier local) n'est plus prise pour un refus de la clé par GitHub. *Tester la connexion* montre aussi ce que git ou ssh a dit, sous son message (dans la fenêtre et dans le terminal).
- **Un dépôt créé deux fois.** Quand un essai précédent avait créé le dépôt puis s'était arrêté, le recréer échouait avec « Repository creation failed. (HTTP 422) » : ce même dépôt, encore vide, est maintenant lié ; un dépôt qui a déjà des commits n'est jamais pris sans être choisi (*Utiliser un de mes dépôts*). La raison de GitHub est donnée quand il refuse un nom.

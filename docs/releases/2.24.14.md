## What's new in 2.24.14

Move to Go, phase 2, step 2.1: the detection of the PC's software.

- **`athanor detecter`** replaces `detect-tools.sh` for the pilot and for the *PC software detected* line of *Setup & health*: Unreal Engine, Blender, the Android SDK and its Java, Roblox Studio, winget, Docker and the toolchain (Node, Python, Git, Java, Go, Rust…), written into the same `system/pc_tools.env` and `.athanor/PC_TOOLS.md`. In native Windows, paths are written as Git Bash knows them, as before.
- **Fixed**: with Unreal or Blender installed on two drives, the newest version is chosen by its number, whatever the drive (the drive letter used to win: UE_5.9 on D: before UE_5.10 on C:). The script is fixed the same way.
- As before, the script stays for when the kit's executable cannot be used, or with `ATHANOR_OUTILS=python`.
- The CI now puts the failing tests in the run's annotations, so that the Windows run can be read without its whole log.
- **Checked against the script**: a fake Windows seen from WSL (drives, `cmd.exe`, `wslpath`, `powershell.exe`) with several Unreal and Blender versions on several drives, the Android SDK and Java, three Roblox Studio versions, tools that answer with colours, `\r`, Java's "Picked up" lines, no version, an error or a long line; without Windows, without Docker, with Claude's desktop, and with every path forced; plus version sorting against `sort -V`. In the pilot's test bench, the real detection gives the same files with both.

## Nouveautés de la 2.24.14

Passage à Go, phase 2, étape 2.1 : la détection des logiciels du PC.

- **`athanor detecter`** remplace `detect-tools.sh` pour le pilote et pour la ligne *Logiciels du PC détectés* d'*Installation & santé* : Unreal Engine, Blender, le SDK Android et son Java, Roblox Studio, winget, Docker et les outils (Node, Python, Git, Java, Go, Rust…), écrits dans les mêmes `system/pc_tools.env` et `.athanor/PC_TOOLS.md`. En Windows natif, les chemins sont écrits comme Git Bash les connaît, comme avant.
- **Corrigé** : avec Unreal ou Blender installé sur deux disques, la version la plus récente est choisie par son numéro, quel que soit le disque (la lettre du disque l'emportait : UE_5.9 sur D: avant UE_5.10 sur C:). Le script est corrigé de la même façon.
- Comme avant, le script reste pour quand l'exécutable du kit n'est pas utilisable, ou avec `ATHANOR_OUTILS=python`.
- La CI met maintenant les tests en échec dans les annotations de l'exécution, pour lire celle de Windows sans tout son journal.
- **Vérifié contre le script** : un faux Windows vu depuis WSL (disques, `cmd.exe`, `wslpath`, `powershell.exe`) avec plusieurs versions d'Unreal et de Blender sur plusieurs disques, le SDK Android et Java, trois versions de Roblox Studio, des outils qui répondent avec des couleurs, des `\r`, les lignes « Picked up » de Java, sans version, en erreur ou avec une ligne trop longue ; sans Windows, sans Docker, avec le bureau de Claude, et avec tous les chemins imposés ; plus le tri des versions contre `sort -V`. Dans le banc d'essai du pilote, la vraie détection donne les mêmes fichiers avec les deux.

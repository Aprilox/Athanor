## What's new in 2.17.0

- **The lead can choose the model of each sub-agent.** With `SUBAGENT_MODEL=auto` (*Settings*, "chosen by the lead"), the lead sets the model of every sub-agent call itself: Haiku for mechanical work, Sonnet for most of the work, Opus only for judgement (architecture, a bug not understood after two tries, the final critique). A call that sets none keeps the usual model (`executor` on `CHEAP_MODEL`, `scout` on Sonnet, the others on the lead's model).
- **Fewer conflicts between parallel workers.** Two milestones whose sheets name the same files no longer run at the same time: the second one starts as soon as the first is done, while the others go on. Files named by 3 milestones or more (routes, `package.json`, shared types…) are not counted, so that the work does not become serial.
- **A cheaper verification after a clean wave.** When every worker merged cleanly, the verification of the cycle runs on `WORKER_MODEL`. The lead's model takes over only for a conflict or a failure.
- **Partial work picked up properly.** A worker that resumes its branch first brings it up to date with the work merged since. The branches of milestones already done are deleted. Milestones numbered like `M7.1` are recognised.
- **Lighter instructions.** The parts only some cycles need (the framing steps, the user's tasks, the final report headings) moved to `.athanor/guides/`. They come with the cycles that need them instead of every turn of every cycle.

## Nouveautés de la 2.17.0

- **Le chef peut choisir le modèle de chaque sous-agent.** Avec `SUBAGENT_MODEL=auto` (*Réglages*, « choisi par le chef »), le chef fixe lui-même le modèle de chaque appel de sous-agent : Haiku pour le travail mécanique, Sonnet pour l'essentiel du travail, Opus seulement pour le jugement (architecture, bug toujours incompris après deux essais, critique finale). Un appel qui n'en précise pas garde le modèle habituel (`executor` sur `CHEAP_MODEL`, `scout` sur Sonnet, les autres sur le modèle du chef).
- **Moins de conflits entre ouvriers en parallèle.** Deux jalons dont les fiches citent les mêmes fichiers ne tournent plus en même temps : le second démarre dès que le premier a fini, pendant que les autres continuent. Les fichiers cités par 3 jalons ou plus (routes, `package.json`, types partagés…) ne comptent pas, pour que le travail ne devienne pas séquentiel.
- **Une vérification moins chère après une vague sans accroc.** Quand tous les ouvriers ont fusionné sans conflit, la vérification du cycle tourne sur `WORKER_MODEL`. Le modèle du chef ne reprend la main qu'en cas de conflit ou d'échec.
- **Le travail partiel bien repris.** Un ouvrier qui reprend sa branche la remet d'abord à jour avec ce qui a été fusionné depuis. Les branches des jalons déjà faits sont supprimées. Les jalons numérotés comme `M7.1` sont reconnus.
- **Des consignes plus légères.** Les parties dont seuls certains cycles ont besoin (les étapes du cadrage, les tâches pour l'utilisateur, les rubriques du rapport final) sont passées dans `.athanor/guides/`. Elles accompagnent les cycles qui en ont besoin au lieu de chaque tour de chaque cycle.

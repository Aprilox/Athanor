## What's new in 2.43.0

- **Ponytail, built in and on by default**: Claude builds each milestone with the smallest complete change, following the rules of [Ponytail](https://github.com/dietrichgebert/ponytail) 5.3.2 (MIT): reuse what the project, the standard library or an installed dependency already has, then the minimum that fully works, with a small test for non-trivial logic. **Every** Claude session of a project gets it: the lead, the parallel workers, every sub-agent (Athanor's and your own) and the app's chat; those that plan, explore or judge (the framing, `architect`, `scout`, `critic`, the read-only agents, a chat question) get its lean way of working: read only what is needed, answer short, and for `critic`, report the code that should be smaller. An Athanor line sets its reach: Ponytail decides how a milestone is built, never how much of the request is delivered. *Settings → Simplest code* (`PONYTAIL`) switches it off; *Setup & health* checks it.
- **The savings in the Overview**, measured only: in *Usage*, what the cache saved on reading (list price), the tokens RTK spared, and, once there are 3 successful cycles of each kind, the average cost of a cycle with and without Ponytail and the eco mode on the project (a trend, the milestones differ). In a terminal, the same in one line of the *Progress* box.
- **RTK's measures are kept**: they were lost in Claude's sandbox; they now go to the project's workshop (`.athanor/rtk/`, out of git), and the pilot reads them after every cycle. RTK's telemetry stays off.
- `stats.tsv` gets three columns: what each cycle ran with (`ponytail`, `eco`, `rtk`, `cadrage`) and what RTK received and spared.

## Nouveautés de la 2.43.0

- **Ponytail, intégré et activé par défaut** : Claude réalise chaque jalon avec la plus petite modification complète, selon les règles de [Ponytail](https://github.com/dietrichgebert/ponytail) 5.3.2 (MIT) : réutiliser ce que le projet, la bibliothèque standard ou une dépendance installée offre déjà, puis le minimum qui fonctionne entièrement, avec un petit test pour la logique non triviale. **Toutes** les sessions Claude d'un projet le reçoivent : le chef, les ouvriers en parallèle, chaque sous-agent (ceux d'Athanor et les vôtres) et la discussion de l'appli ; ceux qui planifient, explorent ou jugent (le cadrage, `architect`, `scout`, `critic`, les agents en lecture seule, une question dans la discussion) reçoivent sa façon de travailler sobre : ne lire que le nécessaire, répondre court et, pour `critic`, signaler le code qui devrait être plus petit. Une phrase d'Athanor fixe sa portée : Ponytail décide comment un jalon est construit, jamais combien de la demande est livré. *Réglages → Code le plus simple* (`PONYTAIL`) le désactive ; *Installation & santé* le vérifie.
- **Les économies dans le Suivi**, uniquement mesurées : dans *Consommation*, ce que le cache a économisé à la lecture (tarif public), les jetons épargnés par RTK et, dès 3 cycles réussis de chaque sorte, le coût moyen d'un cycle avec et sans Ponytail et le mode éco sur le projet (une tendance, les jalons diffèrent). Dans un terminal, la même chose en une ligne du cadre *Avancement*.
- **Les mesures de RTK sont gardées** : elles se perdaient dans le bac à sable de Claude ; elles vont maintenant dans l'atelier du projet (`.athanor/rtk/`, hors de git), et le pilote les relève après chaque cycle. La télémétrie de RTK reste coupée.
- `stats.tsv` gagne trois colonnes : ce avec quoi chaque cycle a tourné (`ponytail`, `eco`, `rtk`, `cadrage`) et ce que RTK a reçu et épargné.

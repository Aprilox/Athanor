## What's new in 2.49.0

- **Subscription or API key.** *Settings → Claude → Connection → Connect with*: your Claude subscription (its token, as before) or an API key, each run billed to the API account. Only the chosen one reaches Claude Code: with both set, Claude Code would have billed the key. A warning in API mode says what changes: the plugins and connectors of a claude.ai account (Gmail, Drive… added in the Claude app) do not work with a key; the Skills, the MCP servers and every extension of Athanor work the same. *Setup & health* checks the key (and says when the API account has no credit left), *athanor configurer* asks which one, and the terminal's *T* asks for the key in API mode.
- **The API spend in place of the quota.** With an API key, *Overview* shows what Claude cost since the count started (what Claude Code reports at the end of each run, at list price), against a budget when you set one (*API budget*, the credit left on the API account): spent, left, a bar. Once it is spent, or when the API says the account has no credit left, the pilot waits instead of failing cycle after cycle; a higher budget, *Count again from now* (credit added) or another key, and it resumes at once. Saving a new key or a first budget starts the count again; a budget raised later keeps it. In a terminal: *$* on the Overview, or `athanor depense [zero]`.
- **A new token or key, used at once.** The pilot reads the connection again at each cycle and every few seconds of its waits: a token or a key saved in *Settings* while it waits for the quota, a connection problem, the budget or the credit (another account, a key with credit left) cuts the wait short and the next cycle runs with it. The fallback model and the workers' pause that were the old account's quota are let go.
- **Several computers: a milestone never built twice when two pushes cross.** When another computer pushed at the same moment, GitHub refused the push ("cannot lock ref", "incorrect old value") and the milestone just built stayed on this computer while it went on: another one could take it and build it again. The others' work is now merged and the push tried again, and a milestone built whose push has not gone yet stays this computer's in its presence until it does.

## Nouveautés de la 2.49.0

- **Abonnement ou clé API.** *Réglages → Claude → Connexion → Se connecter avec* : votre abonnement Claude (son jeton, comme avant) ou une clé API, chaque passage facturé au compte API. Seule la connexion choisie parvient à Claude Code : avec les deux, Claude Code aurait facturé la clé. Un avertissement en mode API dit ce qui change : les plugins et connecteurs d'un compte claude.ai (Gmail, Drive… ajoutés dans l'appli Claude) ne fonctionnent pas avec une clé ; les Skills, les serveurs MCP et toutes les extensions d'Athanor fonctionnent pareil. *Installation & santé* vérifie la clé (et dit quand le compte API n'a plus de crédit), *athanor configurer* demande laquelle, et le *T* du terminal demande la clé en mode API.
- **La dépense API à la place du quota.** Avec une clé API, *Suivi* montre ce que Claude a coûté depuis le début du décompte (ce que Claude Code indique à la fin de chaque passage, au prix catalogue), face à un budget si vous en fixez un (*Budget API*, le crédit restant sur le compte API) : dépensé, restant, une barre. Une fois le budget dépensé, ou quand l'API dit que le compte n'a plus de crédit, le pilote attend au lieu d'échouer cycle après cycle ; un budget plus haut, *Recompter à partir de maintenant* (crédit ajouté) ou une autre clé, et il reprend aussitôt. Enregistrer une nouvelle clé ou un premier budget relance le décompte ; un budget augmenté ensuite le garde. Dans un terminal : *$* sur le Suivi, ou `athanor depense [zero]`.
- **Un nouveau jeton ou une nouvelle clé, aussitôt.** Le pilote relit la connexion à chaque cycle et toutes les quelques secondes de ses attentes : un jeton ou une clé enregistré dans *Réglages* pendant qu'il attend le quota, un problème de connexion, le budget ou le crédit (un autre compte, une clé qui a encore du crédit) écourte l'attente, et le cycle suivant tourne avec. Le modèle de secours et la pause des ouvriers, qui tenaient au quota de l'ancien compte, sont levés.
- **Plusieurs ordinateurs : un jalon jamais construit deux fois quand deux envois se croisent.** Quand un autre ordinateur envoyait au même moment, GitHub refusait l'envoi (« cannot lock ref », « incorrect old value ») et le jalon tout juste construit restait sur cet ordinateur pendant qu'il continuait : un autre pouvait le prendre et le construire à nouveau. Le travail des autres est maintenant fusionné et l'envoi retenté, et un jalon construit dont l'envoi n'est pas encore parti reste celui de cet ordinateur dans sa présence jusqu'à ce qu'il parte.

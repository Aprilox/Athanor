## What's new in 2.48.0

- **See Blender's work while Claude works in the background.** Blender's server has a choice on its line (*Skills & MCP*), for every project that switches it on:
  - **Background + preview window** (the default on Windows and Linux): Claude runs its scripts with `blender -b -P script.py`, without Blender's MCP tools in its session (the cheapest: no tool descriptions, no screenshots). After each run, the scene it built is saved as `.athanor/blender/athanor-preview.blend` of the folder Claude works in, and a Blender window opens on it, on Claude's desktop when that option is on, and reloads it by itself after each later run (within two seconds). Each folder has its window: workers in parallel are each shown in their own. The window only shows: Claude never drives it, and closing it changes nothing (the next run opens it again). Claude's script runs as it is (its arguments, its errors); a run that fails still shows what it had built.
  - **Background only**: the same, without any window.
  - **In Blender's window (MCP)**: as before, the pilot opens Blender before each cycle and Claude drives it through the MCP server. On a Mac (where Claude runs Blender itself), this stays the window mode.
  In a terminal: `athanor extensions mode-blender KIT ID apercu|arriere-plan|direct`.
- Before, Blender opened empty when the project had no `.blend` (Claude builds with scripts and exports, never a `.blend`): nothing of the work could be seen in it.

## Nouveautés de la 2.48.0

- **Voir le travail dans Blender pendant que Claude travaille en arrière-plan.** Le serveur de Blender a un choix sur sa ligne (*Skills & MCP*), pour tous les projets qui l'activent :
  - **Arrière-plan + fenêtre d'aperçu** (par défaut sous Windows et Linux) : Claude lance ses scripts avec `blender -b -P script.py`, sans les outils MCP de Blender dans sa session (le moins cher : pas de description d'outils, pas de captures). Après chaque exécution, la scène construite est enregistrée en `.athanor/blender/athanor-preview.blend` du dossier où Claude travaille, et une fenêtre Blender s'ouvre dessus, sur le bureau Claude quand cette option est active, puis la recharge toute seule après chaque exécution suivante (en deux secondes). Chaque dossier a sa fenêtre : les ouvriers en parallèle ont chacun la leur. La fenêtre ne fait que montrer : Claude ne la pilote jamais, et la fermer ne change rien (la prochaine exécution la rouvre). Le script de Claude tourne tel quel (ses arguments, ses erreurs) ; une exécution qui échoue montre quand même ce qu'elle avait construit.
  - **Arrière-plan seul** : pareil, sans aucune fenêtre.
  - **Dans la fenêtre de Blender (MCP)** : comme avant, le pilote ouvre Blender avant chaque cycle et Claude le pilote par le serveur MCP. Sur Mac (où Claude lance Blender lui-même), c'est le mode avec fenêtre.
  Dans un terminal : `athanor extensions mode-blender KIT ID apercu|arriere-plan|direct`.
- Avant, Blender s'ouvrait vide quand le projet n'avait pas de `.blend` (Claude construit avec des scripts et des exports, jamais de `.blend`) : rien du travail ne s'y voyait.

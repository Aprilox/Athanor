## What's new in 2.24.20

The cage of the MCP servers, Claude's Linux screen and the Windows MCP servers move to Go (the move of Athanor to Go, step 2.4).

- **`athanor mcp-cage`** builds the cage of a local MCP server (bubblewrap: the system read-only, the project writable, the user's home and the Windows drives hidden, the Claude token kept out), as `system/mcp-jail.sh` did.
- **`athanor ecran`** starts Claude on its own Linux screen (the user's display, Wayland and D-Bus out of reach) and takes its picture for the app, as `system/ecran.sh` did.
- **`athanor mcp-windows`** starts an MCP server that is a Windows program through WSL (its variables to it alone, `%NAME%` read raw from Windows, Claude's desktop, its whole Windows tree stopped with the session, a watchdog if the launcher is killed outright), as `system/windows-mcp.sh` did.
- The three scripts stay the entry points (the MCP configurations and the pilot name them) and hand over to the executable when it runs here; `ATHANOR_OUTILS=python` keeps the scripts. The native Windows shims (`pkill`, `setsid`, `flock`, `jq`) belong to the bash pilot: they go with it (phase 3).
- **Checked**: the cage and the screen's command lines compared with the scripts (21 cases), and every Windows MCP server scenario (keys, tokens kept out, `.bat` and `%VAR%`, Claude's desktop, TERM, KILL and its watchdog, EOF, refusals) with the script and with Go.

## Nouveautés de la 2.24.20

La cage des serveurs MCP, l'écran Linux de Claude et les serveurs MCP Windows passent en Go (passage d'Athanor en Go, étape 2.4).

- **`athanor mcp-cage`** construit la cage d'un serveur MCP local (bubblewrap : le système en lecture seule, le projet en écriture, le dossier personnel et les disques Windows cachés, le jeton de Claude tenu à l'écart), comme le faisait `system/mcp-jail.sh`.
- **`athanor ecran`** lance Claude sur son propre écran Linux (l'affichage de l'utilisateur, Wayland et D-Bus hors d'atteinte) et en prend l'image pour l'appli, comme le faisait `system/ecran.sh`.
- **`athanor mcp-windows`** lance un serveur MCP qui est un programme Windows via WSL (ses variables à lui seul, `%NOM%` lu tel quel dans Windows, le bureau de Claude, tout son arbre Windows arrêté avec la session, un chien de garde si le lanceur est tué net), comme le faisait `system/windows-mcp.sh`.
- Les trois scripts restent les points d'entrée (les configurations MCP et le pilote les nomment) et passent la main à l'exécutable quand il tourne ici ; `ATHANOR_OUTILS=python` garde les scripts. Les shims du Windows natif (`pkill`, `setsid`, `flock`, `jq`) appartiennent au pilote bash : ils partiront avec lui (phase 3).
- **Vérifié** : les lignes de commande de la cage et de l'écran comparées aux scripts (21 cas), et tous les scénarios des serveurs MCP Windows (clés, jetons tenus à l'écart, `.bat` et `%VAR%`, bureau de Claude, TERM, KILL et son chien de garde, fin d'entrée, refus) avec le script et avec Go.

## What's new in 2.19.5

- **Claude can read back its own long outputs.** Claude Code saves a long command output in its own folder for the project (`~/.claude/projects/<project>/`) and reads it from there; the file guard refused that read. That folder is now readable (only this project's, never writable).
- **Native Windows mode:** the pilot opens Roblox Studio (and the other gateways) directly again: it was told "the pilot's bridge is not responding", as there is no bridge without a sandbox. The instructions always go through a file when Claude Code can read them from one (it was detected from its help, which does not list every option), so they never come near the Windows command-line limit. `PC_TOOLS.md` no longer mentions a Linux screen there, and tool versions are written without colour codes.

---

## Nouveautés de la 2.19.5

- **Claude peut relire ses propres sorties longues.** Claude Code range une longue sortie de commande dans son propre dossier pour le projet (`~/.claude/projects/<projet>/`) et la relit de là ; le garde-fichiers refusait cette lecture. Ce dossier est maintenant lisible (seulement celui de ce projet, jamais en écriture).
- **Mode Windows natif :** le pilote ouvre de nouveau Roblox Studio (et les autres passerelles) directement : il recevait « the pilot's bridge is not responding », faute de pont sans barrière. Les consignes passent toujours par un fichier quand Claude Code sait les y lire (c'était détecté par son aide, qui ne liste pas toutes ses options), pour ne jamais approcher la limite de la ligne de commande de Windows. `PC_TOOLS.md` n'y parle plus d'écran Linux, et les versions des outils sont écrites sans codes de couleur.

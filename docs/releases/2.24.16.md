## What's new in 2.24.16

The MCP servers are set in the app, and the program a server drives is described, not written in the pilot.

- **Every MCP server can be edited** (*Skills & MCP › View / edit*): its configuration, its settings and the program to open before each cycle, as one JSON text, for a catalog server as for one pasted by hand. A key pasted there is moved to the protected keys, never kept in the text; a Windows program stays one only when you say so (`"type": "windows"`).
- **All the settings of a server are shown** below it (an address, a port, a path), even those that only the program to open uses.
- **The program to open is part of the server's description** (key `ouvrir`, in the catalog or in your library): the program (a gateway such as `blender`, or a Windows program `C:\…\name.exe`), its arguments (`{FICHIER}`: the project's file found), the project files to look for, the process or the port that says it is already open, and how long to wait for that port. The pilot opens it before each cycle (`athanor mcp-ouvrir`) and says once what went wrong. A new server of this kind needs no change to Athanor. Blender's opening is now described this way; Roblox Studio and Unreal keep theirs.
- The CI shows the failing tests' lines in its annotations.
- **Checked**: the descriptions, the settings filled in, the openings (gateway, Windows program, port answering or not, file found or not), the editing in the app, and the real pilot with the Go helpers and with the scripts.

## Nouveautés de la 2.24.16

Les serveurs MCP se règlent dans l'appli, et le programme qu'un serveur pilote est décrit au lieu d'être écrit dans le pilote.

- **Chaque serveur MCP se modifie** (*Skills & MCP › Voir / modifier*) : sa configuration, ses réglages et le programme à ouvrir avant chaque cycle, en un seul texte JSON, pour un serveur du catalogue comme pour un serveur collé à la main. Une clé collée là est rangée avec les clés protégées, jamais gardée dans le texte ; un programme Windows ne le reste que si vous le dites (`"type": "windows"`).
- **Tous les réglages d'un serveur s'affichent** sous lui (une adresse, un port, un chemin), même ceux dont seul le programme à ouvrir se sert.
- **Le programme à ouvrir fait partie de la description du serveur** (clé `ouvrir`, dans le catalogue ou dans votre bibliothèque) : le programme (une passerelle comme `blender`, ou un programme Windows `C:\…\nom.exe`), ses arguments (`{FICHIER}` : le fichier du projet trouvé), les fichiers du projet à chercher, le processus ou le port qui disent qu'il est déjà ouvert, et combien de temps attendre ce port. Le pilote l'ouvre avant chaque cycle (`athanor mcp-ouvrir`) et ne signale un problème qu'une fois. Un nouveau serveur de ce genre ne demande aucune modification d'Athanor. L'ouverture de Blender est maintenant décrite ainsi ; Roblox Studio et Unreal gardent la leur.
- La CI montre les lignes des tests en échec dans ses annotations.
- **Vérifié** : les descriptions, les réglages remplis, les ouvertures (passerelle, programme Windows, port qui répond ou non, fichier trouvé ou non), la modification dans l'appli, et le vrai pilote avec les outils Go et avec les scripts.
